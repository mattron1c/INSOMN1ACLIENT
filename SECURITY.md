# INSOMN1A PVP — Security & Usage Policy

**Project:** INSOMN1A PVP  
**Minecraft Version:** Java Edition 1.21.11  
**Mod Loader:** Fabric  
**Platforms:** GitHub and Modrinth

## 1. Overview

INSOMN1A PVP is a Minecraft client-side mod designed to provide PvP-related features alongside multiplayer functionality, including friends and messaging.

The project consists of two main components:

- **Client Mod:** The Fabric mod, including its source code and client-side features.
- **Private Backend:** A Paper-based server operated and maintained by the original developer to support online features such as friends, messaging, and other connected functionality.

This policy explains the permissions granted to users, the restrictions surrounding the private backend, and the expectations for securely using or modifying the project.

## 2. Source Code, Modifications & Redistribution

The INSOMN1A PVP client source code is intended to be accessible to the community.

Subject to the applicable software license, users are permitted to:

- Download and use the mod.
- View, study, and modify the source code.
- Create custom versions, forks, and derivative works.
- Add new features, improvements, fixes, and updates.
- Distribute original or modified versions of the client mod.
- Publish their own builds and maintain independent versions of the project.

When redistributing the project or a modified version, users must comply with the applicable license, preserve required copyright and license notices, and clearly identify their modifications where required.

Redistribution must not imply that a modified version is an official release of INSOMN1A PVP unless explicitly authorized.

These permissions apply to the client-side project files covered by the license. They do **not** automatically grant access to the private backend, server credentials, private infrastructure, or any separately licensed components.

## 3. Private Backend & Multiplayer Features

INSOMN1A PVP uses a privately operated Paper backend to provide online functionality, including friends lists, messaging, and other multiplayer services.

Access to this backend is controlled by the original developer.

Users who wish to connect a modified client, integrate with the official backend, or obtain backend access for development or testing must **request permission from the project owner**.

The following rules apply:

- Backend access is not automatically granted by downloading, modifying, or redistributing the client.
- Requests for access may be approved or denied at the developer's discretion.
- Users must not attempt to obtain unauthorized access to the backend or its administrative systems.
- Users must not share private server credentials, access tokens, or other confidential backend information.
- Users must not interfere with the availability, integrity, or security of the backend.
- Permission to access the backend does not grant ownership of the infrastructure or permission to redistribute its private components.

Users are free to develop their own independent backend implementations for modified clients, provided they respect applicable licenses, privacy requirements, and other relevant laws.

**Modifying the client is permitted; unauthorized access to the official backend is not.**

## 4. Security & Responsible Use

Anyone using, modifying, or distributing INSOMN1A PVP is expected to use the project responsibly.

The following activities are prohibited in connection with the official services:

- Unauthorized access to private systems, accounts, or administrative interfaces.
- Attempting to bypass backend authentication or access controls.
- Exploiting vulnerabilities to access another user's private information.
- Disrupting, overloading, or deliberately interfering with the official backend.
- Distributing confidential credentials, tokens, or private server information.

Security vulnerabilities should be reported privately to the project owner rather than publicly disclosed with information that could put users or infrastructure at risk.

The project owner may restrict or revoke backend access when reasonably necessary to protect the service, its users, or its infrastructure.

## 5. Independent Forks & Community Development

Community members are welcome to develop independent forks and contribute improvements to the client.

Forks may introduce new features, redesign existing functionality, fix bugs, or maintain compatibility with future versions of Minecraft, subject to the applicable license and third-party component requirements.

Independent forks are not automatically entitled to use the official backend. They must obtain permission before connecting to restricted services when authorization is required.

Fork maintainers are responsible for their own modifications, distributions, infrastructure, and user support.

## 6. Privacy & Online Services

Features that use the official backend may require information to be transmitted between the client and the server.

Users should only connect to services they trust. Modified clients and unofficial backends may handle information differently from the official version.

The project owner should document the information collected by the official backend, how it is used, how long it is retained, and how users can request its removal, where applicable.

Do not assume that modifying the publicly available client changes the official backend's data-handling practices.

## 7. Availability & Warranty

The official backend is independently operated and may be updated, temporarily unavailable, or discontinued.

Permission to modify or redistribute the client does not guarantee access to the official multiplayer services, continued backend availability, technical support, or compatibility with future releases.

The client and backend are provided subject to the terms of the applicable software licenses and relevant law.

## 8. Policy Changes

This policy may be updated as INSOMN1A PVP develops.

The applicable software license determines the rights granted to users for the versions and components it covers. This policy does not independently expand or replace those license terms.

## 9. Contact & Permission Requests

For backend access, security reports, or other project-related questions, contact the original project owner through the official GitHub repository or the contact method listed on the INSOMN1A PVP Modrinth page.

When requesting backend access, explain your intended use, the client version you are using, and whether the request is for development, testing, or another purpose.
